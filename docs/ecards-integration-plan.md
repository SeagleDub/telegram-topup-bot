# План: банк eCards + «Расход по группе»

## Контекст
Тип работы: **New feature**.

Добавлен третий банк **eCards** во флоу **«💳 Действия с картами»** (по образцу
AdsCard/MultiCards) и функция меню **«💸 Расход по группе»** — байер смотрит
нетто-расход по своим картам за текущий месяц.

Внешний API: `https://ecardsnew.cab/api/modern/api-external/v1` (см. [API.md](../API.md)).
Авторизация статическая: `Authorization: Bearer <ECARDS_TOKEN>` (логина в доке нет).

## Схема ответов (подтверждена живыми примерами)
Все коллекции — пейджинг: `{"data": {"content": [...], "last": ..., "totalPages": ...}}`.
- **`GET /card`** отдаёт полный `cardNumber`, `cardCvv`, `cardExpire`, `status`,
  `currency`, вложенные `account`/`holder`, `sharedBalanceUsed`, `groupsRelations`,
  а также `password3ds`/`last3dsOtp`/`token`. ⚠️ **Чувствительные (CVC, PAN,
  3DS-пароль/OTP, token) в чат НЕ выводим** — показываем маскированный номер + безопасные поля.
- **`GET /card-operation`**: сумма в поле **`value`** (строка), тип **`type`**
  (`debit_authorization` = успешное списание), валюта во вложенной **`card.currency`**,
  карта во **`card.{id,cardNumber}`**, мерчант `merchantInfo`.
- **`GET /card-group`**: `id`, `name`, `ownerId`.

**Ограничение:** смены лимита эндпоинта нет → у eCards только **Блокировка**
(`POST /card/close`) и **Транзакции** (`GET /card-operation`). Поиск карты — **по
номеру** (как adscard/multicards): `cardNumber` в ответе есть.

## Используемые эндпоинты (Bearer)
| Действие | Endpoint | Параметры |
|---|---|---|
| Список карт / поиск | `GET /card` | `search`, `limit` |
| Заблокировать | `POST /card/close` | `{cardsIds:[id]}` |
| Транзакции карты | `GET /card-operation` | `filterCardId[]`, `createdFrom/To`, сортировка по дате |
| Группы карт | `GET /card-group` | `limit` |
| Операции группы | `GET /card-operation` | `filterCardGroupId[]`, `createdFrom/To` (пагинация) |

## Расход по группе
**Название группы содержит Telegram-ID байера** → маппинг байер→группа делается
автоматически, приватность обеспечена (байер видит только свои группы).

1. Байер жмёт «💸 Расход по группе».
2. `GET /card-group` → берём группы, в имени которых tg_id присутствует как отдельный
   числовой токен (`\d+`, не подстрока — `123` ≠ `1234`).
3. По каждой группе `GET /card-operation?filterCardGroupId[]=<id>&createdFrom/To`
   с пагинацией (limit=100), safety-cap на страницы (лог при упоре).
4. Нетто-расход по валютам (`_op_sign` по подстроке типа): `+` списания
   (`debit`/`charge`, вкл. `debit_authorization`), `−` возвраты
   (`refund`/`return`/`revers`/`release`/`unhold`); `declined` и `verification` ($0) не считаем.

## Действия eCards в «Действия с картами»
После выбора банка eCards показываются кнопки (подписи без «по группе»):
- **💸 Расход** — нетто-расход по картам байера (его группы) за выбранный период.
- **📜 Последние транзакции** — сразу последние операции по картам байера **без
  выбора периода** (до `ECARDS_GROUP_TX_LIMIT`=50; API отдаёт ≤100/страницу,
  без date-фильтра). Вывод — **листалка** (одно сообщение, стрелки ◀ ▶, по
  `ECARDS_TX_PAGE`=5). Страницы лежат в state (`tx_blocks`/`tx_header`),
  навигация (`txpage:<n>`) редактирует сообщение.

Период спрашивается только у **Расхода**.

Все периоды считаются в **киевском времени** (`Europe/Kyiv` через `zoneinfo`, DST
автоматом; запасной вариант UTC+2 если нет системных tz-данных — для гарантии
поставить пакет `tzdata`). Границы дня/месяца берутся по Киеву, в API уходят как
UTC, на экране даты показываются киевские (`ecards.kyiv_date`).

**Выбор периода** (только у Расхода): пресеты «Сегодня / Вчера / Текущий месяц /
Прошлый месяц / 7 дней / 30 дней» + «✍️ Свой период» (ввод двух дат через пробел,
форматы `ДД.ММ.ГГГГ`/`ГГГГ-ММ-ДД`; парсит `ecards.parse_period`, при путанице
местами — меняет). Состояния `card_actions_choose_period`/`card_actions_enter_period`.

Плюс ввод номера карты остаётся — для действий по конкретной карте (блок,
транзакции, **🔐 3DS код**).

**3DS код** (кнопка в действиях по карте): берём ленту `GET /notification?filterType[]=code_3ds`
(новые сверху), находим свежую запись с нужным `cardId` в `payload`, показываем
`otpCode` + сумма/мерчант/время. Номер карты маскируется, `password3ds` не выводится.
Реализация: `ecards.get_notifications` / `notif_payload` / `find_latest_3ds`. Матч группы — по tg_id в названии (`services/ecards.group_matches_tg`).
Отдельный пункт меню «💸 Расход по группе» (handlers/card_group_expenses.py) сохранён.
Там период = **текущий 4-недельный цикл** с якорем **10.08.2026** (Киев):
`ecards.current_cycle_period` (`CYCLE_ANCHOR`/`CYCLE_DAYS`). Окно = [начало цикла,
конец 28-го дня]; работает и до якоря (окна продлеваются назад).

**«🔄 Другая карта»**: банк сохраняется → сразу запрос номера следующей карты
(без повторного выбора банка); если банк ещё не выбран — к выбору банка.

## Файлы
- `config.py` — `ECARDS_TOKEN` (base URL захардкожен в сервисе, как у AdsCard).
- `services/ecards.py` (новый) — по образцу `services/multicards.py`, токен статический.
- `keyboards.py` — банк eCards в `get_card_bank_keyboard`, действия банка (без лимита),
  пункт меню «💸 Расход по группе».
- `handlers/card_actions.py` — ветки `ecards` (поиск/карточка/транзакции/блок).
- `handlers/card_group_expenses.py` (новый) — расход по группам байера (матч по tg_id).
- `main.py` — регистрация роутера.

## Открытые вопросы
- Полный список значений `type` в `/card-operation` — классификатор `_op_sign`
  работает по подстроке; если появятся неожиданные типы, свериться с логом.
- Есть ли у eCards эндпоинт смены лимита — если да, добавить кнопку.
- Период жёстко «текущий месяц» — при необходимости добавить выбор диапазона.
- Матчинг группы по tg_id в названии требует, чтобы название содержало tg_id
  (напр. `YUL 123456789 (GOOGLE)`) — согласовано с заказчиком.
